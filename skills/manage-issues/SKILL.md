# Issue 작성·등록

1. 대상 owner/repo와 저장소 Issue 템플릿을 확인한다. 기존 Issue·PR을 검색해 중복과 관련 작업을 찾는다. 저장소와 핵심 재현 조건만 필요할 때 질문한다.
2. 버그는 관찰 현상, 환경·버전, 재현 절차, 예상/실제 결과, 근거, 영향으로 정리한다. 기능·작업은 목적, 범위, 완료 기준, 검증 방법, 제외 범위로 정리한다. 모르는 사실은 미확인으로 남긴다.
3. 제목·본문·라벨·담당자·milestone 초안을 만든다. 저장소에 실제 있는 라벨만 사용한다. 로그 속 인증값·계정 정보는 제거하고 첨부파일 공개 범위를 확인한다.
4. 초안 요청이면 Markdown을 반환한다. 생성·수정이 명시됐다면 요청 범위에서 진행한다. 범위가 바뀌거나 게시 승인이 없으면 먼저 초안을 보여준다. 담당자 지정, 댓글·멘션, close, 새 라벨 생성은 요청에 포함된 경우만 수행한다.
5. 등록 결과를 다시 읽고 URL과 반영 필드를 확인한다. 응답이 끊기면 동일 제목·내용의 기존 Issue부터 확인해 중복 등록을 피한다.

## 도구 선택

사용 가능한 GitHub MCP가 있으면 실제 제공된 스키마를 읽는다. 특정 MCP 이름을 하드코딩하지 않는다. 대안은 `gh issue create --repo OWNER/REPO --title '제목' --body-file /절대경로/issue.md`.

Issue 유형·부모·의존관계 같은 확장 필드는 현재 `gh ... --help`와 API 지원을 확인한 뒤 사용한다. 미지원 옵션을 추측하지 않는다. 수정 전 현재 Issue를 읽고 요청하지 않은 필드를 보존한다.

본문 템플릿은 설치된 `references/templates.md` 참고. 개별 저장소 템플릿을 우선한다.
