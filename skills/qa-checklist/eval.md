# QA 체크리스트 자가 점검

문서를 다 쓴 뒤, 사용자에게 보여 주기 전에 항목마다 통과/실패를 판단한다. 하나라도 실패면 고치고 다시 점검한다.

## 구조

1. 첫 줄에 "이번에 바뀐 것"이 1~2줄로 있는가? 사용자 입장 표현인가?
2. 준비 항목이 전부 체크박스인가? QA가 정할 수 없는 값(계정, 빌드)은 빈칸 + "담당자가 채움"인가?
3. 문서 안에 케이스 ID(`A01`, `TC-`), 다른 문서 링크, `<a id>` 앵커가 없는가?
4. 확인 항목이 한 줄씩이고 `준비. 할 일 → 할 일. → 결과값.` 순서인가?
5. 초 단위 시간 기준이 없는가? "기다린 뒤에도 안 바뀌면 실패"로 썼는가?
5-1. 그룹 순서가 정상 → 잘못된 입력 → 삭제·누락 → 오프라인·재시작 → 회귀인가? 빈 그룹은 뺐는가?

## 내용

6. 각 항목의 "결과값"이 코드에서 근거를 찾은 것인가? 근거 없는 것은 "확인 필요"로 뺐는가?
7. 이식 검사: 항목을 다른 앱에 그대로 옮겨도 말이 되면 구체성 부족이다. 이 앱의 화면 이름, 설정 이름, 값이 들어 있는가?
8. 서버 값, 앱이 쓰는 값, 화면 결과를 섞지 않았는가? "서버 저장 성공"을 "앱 반영"으로 쓰지 않았는가?
9. 토글 항목에 두 값의 의미가 모두 있는가?
10. 존재하지 않는 테스트 버튼·디버그 화면을 준비 완료처럼 쓰지 않았는가?
11. 화면으로 확인 못 하는 동작은 항목에서 빼고 한 줄로 이유를 남겼는가?

## 문장

12. "~합니다"체, 한 문장 20자 안팎, 슬래시·괄호 중첩 없음인가?
13. `기본적으로`, `~하게 됩니다`, `~할 수 있습니다`, `쉽게 말하면`이 남아 있지 않은가?
14. 전문 용어가 처음 나올 때 한 줄 뜻이 붙어 있는가? 만든 용어는 없는가?

## 출력

15. 사용자에게 문서 본문을 다시 설명하지 않고 "확인 필요" 목록만 보여 주는가?
