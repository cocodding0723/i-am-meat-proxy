# 기술 문서 작성

목적·독자·현재 문서를 먼저 확인한다. 대화에서 이미 정한 내용을 다시 묻지 않는다. 구현, 제안, 제공 데이터, 실제 검증 결과를 구분한다.

- 문서의 핵심 결과·사용 방법을 먼저 배치한다. 낯선 개념은 그 개념을 사용하는 설명보다 앞서 정의한다.
- 식별자, 조건, 값, 시점, 예외, 출처는 보존한다. 근거가 없으면 그럴듯한 설명으로 메우지 않는다.
- 절차는 준비 → 행동 → 관찰할 결과 순으로 쓴다. 현재 존재하지 않는 화면·기능·테스트 도구를 가정하지 않는다.
- 처음 읽는 사람 관점에서 목적, 적용 환경, 준비 조건, 실패 처리, 미확인 사항을 검토한다. 자체 검토를 독립 검수로 부르지 않는다.
- 링크·표·용어·도식의 일치를 확인한다. DOCX·PDF·슬라이드는 해당 형식의 렌더링 검증을 함께 수행한다.

한국어 문서에서는 [작성 기준](references/korean-technical-writing.md)을 필요한 만큼 읽는다. 사용자 원문과 무관한 파일을 바꾸지 않는다. 문서 작성 권한과 외부 게시 권한은 구분한다.
